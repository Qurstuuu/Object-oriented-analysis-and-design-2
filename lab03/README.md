# Приложение для поиска файлов
* Проект реализует десктоп приложение для поиска файлов с использованием разных стратегий на Python с Tkinter.
  
### Реализованы следующие функции:
* Поиск дубликатов файлов (по MD5-хешу содержимого)
* Поиск старых файлов (не изменявшихся более 30 дней)
* Поиск текста внутри файлов (поддерживаются .txt, .py, .md, .csv, .json, .xml, .html)
* Поиск файлов по размеру (больше заданного порога)
* Графический интерфейс с таблицей результатов и прогресс-индикацией
* Открытие найденного файла двойным кликом
* Обработка ошибок доступа к файлам (PermissionError, OSError)

### Проблема:
Логика поиска всегда одинакова: обход папок, фильтрация файлов, извлечение информации, сортировка результатов. Однако критерии поиска (дубликаты, дата изменения, текст внутри, размер) сильно различаются. 
Без паттерна пришлось бы писать один огромный метод с условными операторами для каждого типа поиска, что делает код сложным для расширения и поддержки.
## Решение: Паттерн <b>Шаблонный метод</b>

### Программа содержит:
1. Класс FileSearcher - абстрактный базовый класс с шаблонным методом search(), определяющим скелет алгоритма поиска
2. Классы-наследники - конкретные стратегии поиска:
    * DuplicateFinder - поиск дубликатов по MD5-хешу
    * OldFileSearcher - поиск старых файлов по дате модификации
    * TextInFileSearcher - поиск текста внутри файлов
    * SizeBasedSearcher - поиск файлов по размеру
3. Класс SearchApp - графический интерфейс на Tkinter

### Шаблонный метод определяет каркас алгоритма:
* Обход вложенных папок
* Фильтрация по критерию
* Извлечение данных
* Сортировка
  
#### Упростилось расширение функционала
Для добавления нового типа поиска достаточно создать новый класс-наследник и реализовать два абстрактных метода: matches_criteria() и extract_info()

#### Установилась слабая связность
Графический интерфейс не знает о конкретных алгоритмах поиска, работает только с абстрактным классом FileSearcher

#### Улучшилась тестируемость
* Каждую стратегию поиска можно тестировать независимо
* Базовый класс с шаблонным методом тестируется один раз для всех наследников
